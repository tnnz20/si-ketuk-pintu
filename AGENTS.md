# Repository Guidelines

## Project Structure & Module Organization

This repository contains a Go API and a React single-page application.

### Backend (`apps/backend/`)

- `cmd/` contains executable entry points: `web`, `migrate`, and seed tools.
- `internal/config/` wires the application; `internal/delivery/http/` defines routes, middleware, and controllers.
- `internal/usecase/` implements business rules; `internal/repository/` owns GORM persistence; `entity/` and `model/` define database and API shapes.
- `db/migrations/` contains ordered SQL migrations; `test/integration/` tests the live database and HTTP behavior.

Keep dependencies flowing from controllers to use cases to repositories. Do not import `internal` packages across unrelated layers.

### Frontend (`apps/frontend/`)

- `src/pages/` owns route-level screens; `src/components/` contains reusable UI.
- `src/lib/api/` is the backend client; `src/schemas/`, `src/types/`, and `src/constants/` hold validation, shared shapes, and values.
- `public/` holds static files; `dist/` is generated by the build and should not be edited.

Root files: `compose.yaml`, `Makefile`, `API_CONTRACT.md`, and `docs/`.

## Build, Test, and Development Commands

Use `make` from the repository root:

- `make be-run` starts the API at `http://localhost:8080`; first copy `apps/backend/.env.example` to `apps/backend/.env`.
- `make fe-dev` starts the Vite development server; `make fe-build` type-checks and builds it.
- `make be-test-unit` runs Go unit tests. `make be-test` also starts PostgreSQL and runs integration tests.
- `make fe-lint` and `make fe-format-check` validate frontend code; `make fe-prettier` formats it.
- `make migrate-up` applies migrations; create one with `make migrate-create name=add_feature`.

Set `ENGINE=docker`.

## Coding Style & Naming Conventions

Format Go with `gofmt`; use idiomatic exported Go names and concise `CamelCase` types. Keep errors wrapped with operation context (`fmt.Errorf("open database: %w", err)`) so callers can use `errors.Is`.

Frontend code uses TypeScript, ESLint, Prettier, and Tailwind. Components use `PascalCase.tsx`; hooks and helpers use camelCase. Keep API payload names aligned with the backend contract, including snake_case JSON/form fields.

## Testing Guidelines

Add focused Go tests beside the package as `*_test.go`, named `Test<Behavior>`. Use `apps/backend/test/integration/` for database, migration, and HTTP behavior. Verify frontend changes with lint and a production build.

## Commit & Pull Request Guidelines

Use conventional, imperative commit subjects such as `feat: add production turnstile protection`, `fix: normalize admin pagination`, or `docs: clarify bootstrap godoc`. Keep each commit scoped to one concern.

Pull requests should explain user-visible changes, configuration or migration steps, linked issues, and UI screenshots. State commands run before review.

## Security & Configuration

Never commit `.env` files, credentials, JWT secrets, or Turnstile keys. Update `.env.example` when adding required configuration, and keep production-only checks fail-closed.
